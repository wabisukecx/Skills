# Skills

自作のClaude向けスキルを置くリポジトリです。

各 `.skill` は、`SKILL.md`、書式や基準を定めた参照ファイル、処理用のPythonスクリプトなどをまとめたパッケージです。使うときは、対象の `.skill` ファイルをダウンロードし、Claudeのカスタムスキルとして登録します。

| [boardgame-transcription-evaluator.skill](boardgame-transcription-evaluator.skill) | ボードゲーム | 原文と転記を比較し、脱落・言い換え・追記などを評価する。旧版と新版の比較にも対応する |

## ボードゲームのルール確認用

ボードゲームの公式資料を、原文を保持した参照資料に整え、その品質を検査するためのスキルです。

基本的な運用は、**Claudeで資料を作成・検査し、完成した資料と指示書をChatGPTに登録して、プレイ中にChatGPT Liveで音声対話する**形を想定しています。

### 全体の流れ

1. ユーザーが公式ルール・公式FAQ・エラッタなどの生資料を用意する。
2. Claudeで `boardgame-rules-transcriber` を使い、転記Markdownとルール確認アシスタント用の指示書を作る。
3. Claudeで `boardgame-transcription-evaluator` を使い、原文との一致を検査する。
4. 必要な修正と再検査を行い、完成した資料・指示書をChatGPTに登録する。
5. 登録資料を参照できる会話で、ChatGPT Liveを使ってルールを確認する。

このREADMEでは「ChatGPT Live」を、プレイ中にChatGPTと音声でやり取りする運用の呼び方として使っています。

各 `.skill` は、`SKILL.md`、書式や評価基準を定めた参照ファイル、処理用のPythonスクリプトをまとめたパッケージです。

#### boardgame-rules-transcriber：資料を作成する

ユーザーが添付したHTML・PDF・画像・テキストなどから、公式ルール・FAQ・エラッタ・デザイナー回答を参照用Markdownに変換します。

- 原文を保持し、翻訳・要約・独自の裁定を加えません。
- 出典・版・言語・取得日を記録します。
- ページ・条項・確認済みのリンクなど、根拠をたどるための参照を付けます。
- 判読不能箇所、未転記部分、件数の不一致などは明示します。
- 原文と編集注を区別し、版・言語ごとに資料を分けます。

付属の `extract_text.py` は原文の抽出、`verify_transcription.py` は構造・件数などの自己点検を担当します。原文への忠実性は、次の評価スキルで別途確認します。

#### boardgame-transcription-evaluator：資料を検査する

生資料と転記Markdownを比較し、原文がどれだけ忠実に残っているかを評価します。

- `align_and_diff.py` で条項・Q&Aなどを整列し、差分を列挙します。
- 差分の重大度を分類し、合格・条件付き・不合格を報告します。
- 編集注、メタデータ、指示書、資料台帳の整合性も確認します。
- 旧版と新版の転記を比較し、追加・削除・文言変更を確認できます。

原文の添付が必要です。ゲームの一般知識で「正しいルール」を判断するのではなく、原文と転記の対応関係を検査します。

### 基本的な使い方

#### 1. Claudeにスキルを登録する

このリポジトリから2つの `.skill` ファイルをダウンロードし、Claudeのカスタムスキルとして登録します。

このスキルを動かすのは資料作成・検査側のClaudeです。ChatGPT側には、Claudeが作成した資料と指示書を登録します。

#### 2. 公式資料を用意する

出版社などから取得した、対象ゲームの資料をClaudeに添付します。

- 公式ルールブック
- 公式FAQ
- 公式エラッタ
- 出典を確認できるデザイナー・出版社スタッフの公開回答（準公式）

ゲーム名、採用する版、使用する拡張、資料の取得元・取得日・言語なども伝えます。不明な情報は推測で埋めず、「不明」として扱います。

資料の収集はユーザーが行います。スキルは添付資料を処理し、Web検索や一般知識で本文を補いません。

#### 3. Claudeで資料を作成する

依頼例：

> 添付した公式資料をboardgame-rules-transcriberで転記してください。ゲーム名は○○、採用版は○○、使用拡張は○○です。ChatGPTに登録し、プレイ中にChatGPT Liveでルール確認をするための資料一式と指示書を作成してください。原文を保持し、未確認・未転記箇所を明示してください。

主な成果物は次のとおりです。`<slug>` はゲームを識別する英数字の名前です。

| 成果物 | 用途 |
| --- | --- |
| `<slug>_Official_Rules_<版>_<日>.md` | 公式ルール本文の参照資料 |
| `<slug>_Official_FAQ_<版>_<日>.md` | 公式FAQの参照資料。入力資料がある場合に作成 |
| `<slug>_Official_Errata_…md` / `<slug>_Designer_Rulings_…md` | 訂正・準公式回答の参照資料。入力資料がある場合に作成 |
| `<slug>_Assistant_Instructions.md` | ChatGPTの回答方針・参照範囲・音声対話の進め方 |
| `<slug>_Document_Ledger.md` | 資料の版・出典・優先関係・既知の限界を記録した台帳 |
| `<slug>_Setup_Checklist.md` | 作成した資料を登録する手順 |
| `<slug>_Acceptance_Questions.md` | 登録後の動作確認用の質問 |
| `<slug>_Terminology_<日>.md` | 両言語の資料で確認できた用語の対照表。該当する場合に作成 |

#### 4. Claudeで原文との一致を検査する

生資料と作成したMarkdownを添付して依頼します。指示書・台帳も検査対象に含めます。

> boardgame-transcription-evaluatorで、添付した原文と転記Markdownの忠実性を評価してください。脱落・言い換え・原文にない追記を確認し、指示書と資料台帳の整合性も検査してください。修正が必要な箇所を重大度順に報告してください。

指摘された箇所を修正し、再評価します。画像・スキャンはOCR結果や目視転記の中間テキストを比較元にするため、元画像との一致は別途確認が必要です。

#### 5. 完成した資料をChatGPTに登録する

作成された `Setup_Checklist.md` に沿って、ゲームごとの参照環境を用意します。

- `Assistant_Instructions.md` の本文を、利用する環境の指示設定に反映する。
- 転記した公式資料と資料台帳を、会話から参照できる資料として登録する。
- 用語対照表があれば、補助資料として登録する。
- 採用する版と使用拡張を明確にし、旧版は比較用として区別する。

指示書を資料として添付するだけで終わらせず、回答方針として反映します。具体的な登録画面は利用環境に合わせて選び、Liveで使う会話が登録資料を参照できることを確認してください。

登録後は `Acceptance_Questions.md` を使って、次の3点を確認します。

1. 資料にある質問へ、対応する根拠を使って答えられる。
2. 資料で確認できない質問へ、推測で断定せず不足を伝えられる。
3. 「どこに書いてある？」と聞くと、実在する資料名・条項・ページを示せる。

#### 6. ChatGPT Liveでルールを確認する

プレイ中は、状況と疑問を短く伝えます。

> 今は○○の手番です。このカードを使ったあとに、もう一度移動できますか？

> その処理の順番を短く教えて。

> どの資料の、どの条項に書いてありますか？

指示書は、結論と重要な条件を先に短く答え、結論が変わる条件だけを確認する音声対話を想定しています。資料に記載された内容と、複数のルールから導いた判断を区別し、根拠が足りない場合は「登録資料では確認できない」と伝える方針です。

### 資料が更新されたとき

1. 新しい公式資料を用意し、Claudeで転記する。
2. 新しい原文と転記の忠実性を検査する。
3. evaluatorの比較機能で、旧版と新版の転記の差分を確認する。
4. 指示書・資料台帳・検収質問を更新する。
5. ChatGPTの登録資料と指示設定を更新し、再度動作確認する。

旧ファイルは版・日付を付けて保存します。旧版のコンポーネントで遊ぶ場合にも対応できるよう、採用版と比較用の資料を明確に分けます。

### 運用の原則

- 公式資料と準公式回答の出典・位置付けを明確にする。
- 採用版に適用する公式本文・エラッタを優先し、次に公式FAQ、準公式回答を参照する。
- 資料にないルール・翻訳・裁定を作らない。
- 未確認のページ番号・条項・引用を作らない。
- 不明点・欠落・OCRの限界を利用者に見える形で残す。
- 資料の作成、原文との検査、登録後の回答確認をそれぞれ行う。

このセクションのスキルは、ルール確認用の資料と運用指示を作るためのものです。ClaudeからChatGPTへの自動転送や、ChatGPT Liveの設定を自動化する機能は含んでいません。

## レトロゲーム解析用

### nes-reverse-engineering：ROM解析を10工程で進める

ファミコン（NES）のカートリッジROMを解析するためのスキルです。『ファイアーエムブレム 暗黒竜と光の剣』の解析で使った10工程を、ゲームに依らない形にまとめ直しました。

10工程は、ROMの構造把握、起動の流れと状態変数の特定、REA（Ghidra）で読める形への整形、主要なデータ構造の特定、文字コードの解読、計算式の読解、画面に出ない表の抽出、エミュレーター（BizHawk）上での仮説の確定、画像と音での確認、全体の実測照合、という流れです。

スキルが運ぶのは、解析の進め方と確かめ方です。

- 毎回同じ部分（手順、道具の切り替えの判断基準、記録の形式、照合の仕組み）をスキルの本体にします。
- ゲーム依存の部分（アドレス、表の形、マッパー、文字コードの割り当て）はスキルに含めず、対象のゲームごとに取り直します。
- 解析の状態はセッションの中ではなく、確度のラベル（確定／有力／推測）を付けた外部ノートに残します。間違いが見つかったら元の記述は消さず、「訂正」として理由つきで追記します。
- 抽出したデータとエミュレーター上の実測の照合結果をテスト用データとして残し、手順を変えたときの検算（回帰テスト）に使います。
- 数字が出る処理はスクリプトに寄せ、AIは解釈の提案と次に読む場所の提案を担い、確度の「確定」の宣言は人間が行います。

前提環境の例：Windows 11、REA 6.9.0、Ghidra 12.1.4、BizHawk 2.11.1。ROMは自分で所有するものを自分で用意してください。
